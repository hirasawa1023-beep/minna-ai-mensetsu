# さいたま入試ドリル v2.5｜学習記録を教員PCに集約する手順

## まず確認すること

**v2.5は、手書き・文字メモをすぐ使えます。学習記録の自動集約には、学校側で保存先の準備が必要です。**

生徒の本名・学籍番号・受検番号・手書きメモ・文字メモ・解答の文章は送信しません。送るのは、生徒コード、学習日時、教科、単元、問題ID、正誤、セッションの問題数・正答数です。生徒コードと氏名の対応表は別途、教員のみがアクセスできる校内の場所で管理してください。

**学校・自治体の情報セキュリティ規程、校内ICT管理者の確認が完了するまでは送信機能を有効にしないでください。**

## 先生側：Googleスプレッドシートを準備

1. 学校で利用許可されたGoogleアカウントで、新しいGoogleスプレッドシート「さいたま入試ドリル_学習記録」を作成します。**共有設定は非公開にし、担当教員だけ**に限定します。
2. スプレッドシートの「拡張機能」→「Apps Script」を開き、付属の **Code.gs** をエディタに貼り付けて保存します。
3. スプレッドシートを再読み込みすると、メニューに **「入試ドリル」** が表示されます。「① シートを初期設定」を実行します。
4. 「連携コード」シートの **A2以降**に、例 `A01`、`A02`、`B01` のような匿名の生徒コードを入力します。実名は入力しません。
5. メニュー「② 生徒コードの連携コードを発行」を実行すると、各コードのB列に**32文字の個別連携コード**が発行されます。C列は「TRUE」になります。このシートへの閲覧権限は厳格に制限してください。
6. Apps Scriptの「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」。実行ユーザーは**自分**に設定。アクセスできるユーザーは、学校の規程とネットワーク条件に合わせて設定してください。学校ドメイン内限定が使える場合はそれを優先します。ドメイン内限定で外部サイトからの送信が機能しない場合、**校内ICT管理者の許可なく「全員／誰でも」に緩めないでください。**
7. 公開されたウェブアプリURL（`https://script.google.com/macros/s/…/exec`）をコピーします。URLは `/exec` で終わります。
8. **テスト用生徒コード1名だけ**で、下記の生徒側の操作を行い、シートの受信と集計を確認します。本格運用はテスト後に始めてください。

## 生徒側：タブレットの初期設定

1. いつものClassroomの入試ドリルのリンクから、v2.5を開きます。
2. 左の「☁ 記録を先生に送る」を開きます。
3. 先生のウェブアプリURL、自分の生徒コード（例：`A01`）、自分専用の連携コード（32文字）を入力します。
4. 「保存して送信を有効にする」を選びます。これ以降は、ドリル・セット・模擬テストが終わるたびに、学習結果を送信しようとします。
5. 送信成功の表示が出た場合も、最初の利用時は先生がスプレッドシートで受信を確認してください。

## 教員用PCで見る場所

同じスプレッドシートを開けば、次のシートにデータが反映されます。

| シート | 何が分かるか |
|---|---|
| 生徒別集計 | 生徒コードごとの学習回数、問題数、正答率、最終学習日 |
| 単元別集計 | 生徒コード・国語／数学・単元ごとの解答数、正答率 |
| 学習セッション | いつ、どの教科・種類を、何問解いたか |
| 解答詳細 | 各問題IDの正誤（答案そのものは保存しない） |
| 連携コード | 生徒コードと秘密の連携コード。先生のみ閲覧 |

送信が完了しないときは、生徒のタブレットの「記録を先生に送る」にある「未送信の記録を送る」を選び、スプレッドシートの最新行を確認してください。二重送信されても同じセッションIDでは重複して登録しない仕組みです。

## 筆算・考え方のメモ

各問題の下にある「✍️ メモ・筆算」を開きます。指・タッチペンで書けるほか、テキスト欄に解き方の順序を書くこともできます。「ペン」「消しゴム」「ひとつもどす」「ぜんぶ消す」に対応しています。**問題IDごとに同じブラウザー内に残り、クラウドには送信されません。**

生徒の思考過程を先生が確認する場合は、その場で画面を見せてもらってください。将来、メモの提出機能を追加する場合は、学校の個人情報保護・作品保存のルールを先に確認してください。

## 重要な制限

- GitHub Pagesだけでは学習結果の集約はできません。今回添付したGoogle Apps Scriptの**実際のデプロイ**が必要です。現在、アプリの送信機能は初期状態でOFFです。
- 現在の実装では**v2.5以降に完了した学習**を送信待ちとして保存します。以前のv2.4以前の履歴は自動的に一括移行されません。
- 学校のブラウザー制限・サードパーティCookie制限・Google Apps Scriptの公開範囲によって送信が失敗する場合があります。画面上で受信確認が戻らない場合はスプレッドシートを直接確認してください。
- 生徒コードと秘密の連携コードはタブレットのブラウザー内に保存されます。**共用端末の複数生徒による使い回しは禁止**とし、別の生徒へ端末を貸す際は送信停止・記録の整理を行ってください。
- 連携コードはURLや公開HTML・Classroomの共有投稿に一括掲載しないでください。個別に安全な方法で配布してください。
- データの保管期間、削除方法、アクセス権限を学校で決めてから本格運用してください。
